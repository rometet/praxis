# PraxisCompanion architecture (26.51.5)

PraxisCompanion is the utility mod; LHolo owns schematic projection and placement. The Companion runtime has seven named feature slots and does not load schematic code.

`RuntimeConfig` is the persisted request. `runtimeSettings` filters it against confirmed native capability bits and publishes an immutable `Settings` snapshot. Hook callbacks read that snapshot. A setting change republishes when any field changes, including Fullbright brightness or Zoom options. Version 1 config is merged into version 2 defaults, backed up as `config.json.v1.backup`, then written as version 2. The six version 1 feature values and the eleven NoRender pass flags are preserved; a version 1 Zoom multiplier is converted to its effective FOV.

`Native.cpp` installs named LeviLamina typed hooks and subscribes to public input/world events. The exact 26.51.5 client Fake Headers are compiled by `PraxisCompanionNativeProbe`. `Runtime.cpp` owns player generation, Fullbright readiness, Zoom state and config persistence. `WorldOverlays.cpp` submits native ChunkBorders geometry through typed `Tessellator` and `mce::Mesh` APIs. `LightOverlay.cpp` and `RedstoneOverlay.cpp` reuse that world-render call but keep separate bounded, center-first scans and owned numeric sample caches. They use typed `BlockSource` and block state APIs; no borrowed block or item pointer is retained. Their meshes rebuild only when samples or settings change. Chunk lines and overlay cells have independent budgets.

`ShulkerPreview.cpp` uses LeviLamina's UI render event and the Fake Header `ContainerScreenController::mHoveredSlotData` to identify the current inventory item. It decodes `BlockEntityTag.Items` synchronously into 27 owned `ItemStack` instances and copies title/count/name data. The native `ItemRenderer` draws those icons in the same UI event. Hover change, NBT hash change and world generation invalidate the snapshot; no borrowed hovered `ItemStack` pointer survives the callback.

`GuiBackendCoordinator` selects on the first UI render retry after mod enable. Without LHolo, `StandaloneGuiHost` uses the old Praxis DXGI method discovery, owns a separate ImGui/Win32/DX11 context and uses D3D11On12 for D3D12 Minecraft. It hooks Present/Present1, resize and direct command queue capture only in this mode. The same `drawPraxis`/chunk HUD content is used for both modes. With a compatible LHolo PR #12 provider, `LholoBridgeGuiHost` registers those callbacks inside the actual `LHolo.dll` frame; Companion installs no second graphics or WndProc hook. Companion resolves LHolo through LeviLamina's NativeMod registry and the bridge checks ImGui version and structure sizes. With LHolo but no compatible bridge, GUI selection is conflict blocked while native utility features continue. A provider appearing after standalone selection closes that GUI and removes its hooks; a restart is required to choose the bridge. No live ImGui context migration occurs.

Current implementation status is recorded in [FEATURE_PORT_MATRIX.md](FEATURE_PORT_MATRIX.md). Minecraft runtime behavior and LHolo input handoff remain to be tested in game.
